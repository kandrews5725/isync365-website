Security & Compliance

Built with PII lifecycle and access control in mind from day one.

As a contact distribution platform, everything below reflects how contact data moves, where it lives, and what happens when someone's access changes.

Where your contact data actually lives

Some contact-sync tools deliver mobile updates by writing into an app or account the employee already has on their phone. iSync365 avoids this by using a dedicated, company-provisioned CardDAV account — never a personal one.

Two ways in, one standard of security

For company-managed devices, iSync365 can deploy a configuration profile the same way most enterprise tools do. For personal or unmanaged devices — no MDM, no company profile — we generate a separate, human-readable passphrase for that device's CardDAV account: long and random enough to resist brute-force guessing, short enough that someone can type it in by hand without errors. Each device gets its own distinct credential, and failed logins are rate-limited.

Revocation happens automatically, no device cooperation required

When someone's removed from a contact list, nothing needs to happen on their device. The connection can stay in place; it's simply empty of anything they no longer have access to. The next sync clears it out on its own — there's no remote wipe command to send and no dependency on a management profile being present to enforce it.

Clean offboarding, no orphaned data

List membership functions as a real access-control decision, admin-controlled per list. When an employee leaves the company or changes roles, removing them from lists is the whole process — nothing lingers on a personal or field device after the fact.

EAS vs. CardDAV — why the protocol underneath matters

Many contact-sync tools rely on Exchange ActiveSync (EAS), a protocol Microsoft first shipped in the mid-2000s. Microsoft itself is now phasing it out: starting in 2026, Exchange Online will stop accepting outdated EAS client versions, and by the end of the year, EAS's legacy certificate-based authentication method is being retired in favor of modern, Entra ID-based authentication. Security researchers have also documented real vulnerabilities in legacy EAS implementations, including credential exposure under certain conditions.

iSync365 doesn't rely on EAS at all. Mobile devices connect over CardDAV, an open, modern standard — paired with per-device credentials and Microsoft Graph on the Outlook side, both built around current authentication practices rather than a protocol Microsoft is actively retiring.

True zero-touch setup, even on Microsoft 365

Because Apple automatically upgrades Exchange ActiveSync connections to Microsoft 365 to use OAuth authentication, EAS setup always requires the user to sign in manually — even when pushed through MDM. There's no way to pre-fill that step; it's a requirement of OAuth itself, not a configuration limitation.

iSync365's CardDAV connection doesn't have that constraint. The credential can be included directly in the setup profile, so the address book appears on the device fully configured — no sign-in step, no prompt, nothing for the employee to do. And because our CardDAV server is one we operate — not a third party requiring its own sign-in flow — standard credential-based authentication remains a fully supported part of how it works, not something being phased out from under it.
